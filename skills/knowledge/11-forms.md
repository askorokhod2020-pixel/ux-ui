# Формы на сайте

Форма — место, где пользователь платит временем и данными. Каждое лишнее поле снижает конверсию.

## 1. Структура
1. **Минимум полей.** Для каждого поля спроси себя: без него точно нельзя? Можно ли узнать это позже?
2. **Одна колонка.** Многоколоночные формы читаются хуже. Исключение — логически связанные короткие поля (город и индекс, дата и время).
3. **Логичный порядок**: от простого к сложному, как в разговоре (имя → контакты → детали).
4. **Группировка** длинных форм по смыслу с заголовками групп. Очень длинные формы делим на шаги с индикатором прогресса.
5. **Заголовок формы** говорит, что получит пользователь: «Получить консультацию», а не «Форма обратной связи».

## 2. Поля
- **Лейбл над полем**, всегда видимый. Плейсхолдер не заменяет лейбл: он исчезает при вводе.
- Плейсхолдер — только пример формата: «+7 900 000-00-00».
- **Ширина поля** соответствует ожидаемому ответу: индекс короче адреса.
- Высота поля 44–56 px, на мобильном не меньше 48, текст не мельче 16 px (иначе iOS зумит).
- Обязательные поля помечаем, если их меньшинство, необязательные — словом «(необязательно)», если наоборот.
- **Правильный тип и автозаполнение**: `type="email"`, `type="tel"`, `inputmode="numeric"`, `autocomplete="name | email | tel | street-address | one-time-code"`.
- **Маски** для телефона, карты, даты, но с возможностью вставить данные в любом формате.
- Выбор из 2–5 вариантов — радиокнопки (все видны сразу). Больше 5–7 — выпадающий список с поиском.
- Переключатель (switch) — для мгновенного действия. Чекбокс — для выбора, который применится после отправки.
- Пароль: кнопка «показать», требования видны заранее, а не после ошибки.

## 3. Валидация и ошибки
- Проверяем **при потере фокуса** (blur), а не на каждый символ. Ошибку убираем сразу, как только значение стало верным.
- Ошибка **под полем**, рядом с проблемой. Красная обводка + текст + иконка: не только цвет.
- Текст ошибки говорит, как исправить: «Введите email в формате name@mail.ru», а не «Неверный формат».
- При отправке с ошибками — фокус на первое ошибочное поле, сводка ошибок сверху для длинных форм.
- Введённые данные никогда не стираются при ошибке.

## 4. Кнопка отправки
- Название — действие и результат: «Записаться на пробный урок», «Отправить заявку».
- Кнопка не задизейблена до заполнения формы. Лучше дать нажать и показать, что исправить.
- Ширина: на мобильном на всю ширину, на десктопе по контенту или по ширине формы.
- Второстепенные действия («Отмена», «Назад») визуально слабее.
- Рядом с кнопкой снимаем страхи: «Без спама», «Перезвоним в течение 15 минут», ссылка на политику обработки данных.

## 5. Состояния
- Поле: пустое, фокус, заполнено, ошибка, успешно проверено, отключено, только чтение.
- Кнопка: обычная, hover, фокус, нажата, загрузка (спиннер в кнопке, повторное нажатие заблокировано), отключена.
- Форма: заполнение → отправка → **успех** (что произошло и что дальше) или **ошибка сервера** (что делать, данные сохранены).

## 6. Доступность
- Каждое поле связано с `<label>`.
- Ошибки связаны с полем (`aria-describedby`) и озвучиваются.
- Форма полностью проходится клавишей Tab, Enter отправляет.
- Фокус чётко виден.

## Чек-лист формы
- [ ] Каждое поле оправдано
- [ ] Одна колонка, логичный порядок
- [ ] Лейблы над полями, плейсхолдер только как пример
- [ ] Правильные `type`, `inputmode`, `autocomplete`
- [ ] Валидация по blur, ошибки текстом под полем
- [ ] Кнопка названа действием и не задизейблена
- [ ] Есть состояния загрузки, успеха и ошибки сервера
- [ ] Поля на мобильном ≥ 48 px, текст ≥ 16 px
