Ты собираешь финальный артефакт мини-курса — **одностраничный рабочий прототип** из всего, что ученик собрал в предыдущих уроках. Команда работает в две фазы.

## Фаза 1 — проверка подключения к Figma

1. Прочитай `opencode.json` в корне проекта.
2. Найди в блоке `mcp.figma.environment.FIGMA_API_KEY`. Это либо плейсхолдер вида `ВСТАВЬ_СЮДА_СВОЙ_PAT_ИЗ_FIGMA`, либо реальный токен.

**Если плейсхолдер** — ученик ещё не подключил Figma. Напиши в чат точно такое сообщение (только этот текст, без префиксов и пояснений):

> Чтобы я мог читать твои макеты в Figma, нужен Personal Access Token. Сделай так:
>
> 1. Открой Figma → клик по своей аватарке справа сверху → Settings.
> 2. Вкладка Security → секция Personal access tokens → кнопка «Generate new token».
> 3. Дай имя (например, `opencode-mini-course`), scopes на чтение оставь дефолтные, создай.
> 4. Токен показывается один раз. Скопируй и отправь его мне следующим сообщением.

Дождись ответа ученика с токеном. Когда придёт строка, похожая на PAT (`figd_...` или `figu_...` — обычно 40-60 символов):

3. Через свой Write-инструмент перепиши `opencode.json`, заменив значение `FIGMA_API_KEY` на полученный токен. Остальную структуру конфига **не трогай**.
4. Напиши в чат:

> Токен сохранил в `opencode.json`. Чтобы Figma MCP подхватил его, нужно перезапустить OpenCode — закрой и открой заново. После перезапуска снова напиши `/prototype`, и я продолжу.

На этом фаза 1 заканчивается. Дальше ученик перезапускает OpenCode сам.

**Если в FIGMA_API_KEY реальный токен** — фазу 1 пропускаем, идём в фазу 2.

## Фаза 2 — генерация прототипа

1. Прочитай `outputs/prd.md` — PRD продукта из Урока 1.
2. Прочитай `outputs/brand_inputs.md` — бренд-инпуты из Урока 3 (Brand Name, About, Audience, Colors). Если файла нет — мягко уточни у ученика цветовое направление и продолжай.
3. Спроси у ученика **ссылку на Figma-файл с экранами**:

   > Дай ссылку на свой Figma-файл с экранами из прошлого урока. Лучше с правами View by anyone with the link, чтобы я гарантированно прочитал.

4. Получив ссылку, через **Figma MCP** (`figma-developer-mcp`) достань структуру файла: список фреймов / экранов, текстовые узлы, цвета, типографику, бренд-ассеты (изображения).

5. Собери **один интерактивный HTML-файл** — `outputs/prototype.html`. Это критично: всё в одном файле, чтобы ученик мог одним drag-and-drop задеплоить его на Netlify Drop и получить публичный URL.

   **Технические требования:**

   - **Без зависимостей**: без npm, без CDN, без внешних CSS/JS. Всё в одном `.html`. Открывается двойным кликом в браузере.
   - **CSS встроен** в `<style>` внутри `<head>`. **JS встроен** в `<script>` в конце `<body>`.
   - **Все экраны (обычно 3-5 штук из макета)** идут как `<section class="screen">` внутри одного контейнера. Активный экран показывается через класс `.active`. Остальные физически в DOM, но скрыты (через `opacity:0; pointer-events:none; transform: translateY(20px)` или аналогично).
   - **Никаких сторонних библиотек анимации** — vanilla CSS transitions + JS event listeners. Хватает.

   **Интерактивность и анимации (обязательно):**

   - **Плавные переходы между экранами** через CSS `transition` на `opacity` и `transform`. Длительность ~300-500 ms, easing `ease-out`. Никаких мгновенных `display:none`-переключений.
   - **Анимация появления элементов** на активном экране — заголовок, контент, CTA-кнопки появляются с лёгким staggered fade-in + transform (≈ 50-100 ms задержка между элементами).
   - **Hover-состояния** на всех интерактивных элементах: кнопки, карточки, ссылки. Минимум — изменение `background` / `transform: translateY(-2px)` / `box-shadow`.
   - **Focus-состояния** на полях ввода — обводка цветом из палитры бренда.
   - **Активные состояния клика** — `:active` с лёгким `scale(0.98)`, чтобы тактильно ощущалось.
   - **Микровзаимодействия** — где уместно: галочки появляются с bounce-эффектом, прогресс-бары заполняются плавно, чек-марки на карточках при выборе и т.п.

   **Навигация:**

   - Клик на action-кнопку («продолжить», «дальше», «отправить», «начать» — определи по контексту экрана) переключает активный экран на следующий по логике PRD.
   - Кнопка «назад» (если в макете есть) — на предыдущий экран.
   - Сохраняй историю экранов в JS-массиве, чтобы back работал стабильно.

   **Бренд:**

   - Цвета и типографика — из `brand_inputs.md` и из Figma-структуры. Используй CSS custom properties (`--brand-bg`, `--brand-fg`, `--brand-accent`) в `:root` — так легко править палитру руками.
   - Hero-изображение и логотип из Figma выгружай через MCP и встраивай как `<img>` с `data:image/...;base64,...` (чтобы файл оставался самодостаточным после Netlify Drop).
   - Если в Figma ассет публично доступен по URL — допустимо вставлять ссылку.

   **Формы:**

   - `<input>`, `<textarea>`, `<select>` — рабочие, можно вводить и валидировать на клиенте.
   - Данные не сохраняются между перезагрузками — это нормально для прототипа.

   **Адаптив:**

   - Desktop-приоритет (1280-1920 px). На мобильном допустимо «как есть», без отдельной mobile-вёрстки.

6. Сохрани в `outputs/prototype.html` через Write-инструмент.

7. Напиши в чат:

   > Прототип готов: `outputs/prototype.html`. Открой двойным кликом в браузере. Если хочешь публичную ссылку — перетащи файл на `app.netlify.com/drop`, получишь URL вида `random-name.netlify.app` за пару секунд.

## Если данных в PRD или Figma не хватает

Не выдумывай тексты, которых нет в макете. Если у фрейма нет понятного текстового заголовка — оставь короткий placeholder и в конце вывода добавь блок «## Что я предположил» со списком мест, которые ученик может уточнить и попросить меня перегенерировать.

## Если MCP-вызов к Figma не вернул структуру

Возможные причины: токен невалидный, файл закрыт от доступа, неверная ссылка. Скажи ученику:

> Не получилось прочитать Figma-файл по ссылке. Проверь: 1) файл открыт для просмотра по ссылке (Share → Anyone with the link → can view); 2) ссылка ведёт именно на Figma Design (не FigJam, не Slides); 3) токен в `opencode.json` валиден — можно перевыпустить в Figma и удалить старый.

## Тон

Сухо, конкретно. Двухфазная природа команды — это нормально, не извиняйся за необходимость перезапуска. Один раз настроили, дальше работает.
